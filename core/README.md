# Core Infrastructure

This folder contains all playback and pattern-parsing logic—both the C++ and JavaScript implementations, plus shared test fixtures.

## Contents

- **test-cases.json** — Shared source patterns used to validate both implementations
- **test-cases-ast.json** — Golden AST snapshots (generated by running `npm run update-ast-cases`)
- **[cpp/](cpp/)** — C++ implementation (parser, renderer, harmony modules, tests)
- **[js/](js/)** — JavaScript implementation (primary runtime; parser, renderer, playback, harmony)

## Using Core

### JavaScript Implementation
For most users (web app, Node.js):
```bash
cd core/js
npm test
```

### C++ Implementation
For validation, embedding, or performance testing:
```bash
cd core/cpp
./prepare_build.sh
cd build && cmake --build .
./Tests.exe
```

## Test Cases

All test cases are defined in a single shared fixture: `test-cases.json`. Both implementations parse this file and validate their AST output against `test-cases-ast.json`.

To regenerate the AST snapshot after intentional parser changes:
```bash
npm run update-ast-cases  # from root
```

This runs the JavaScript evaluator on all test cases and updates `test-cases-ast.json`.

## Parity

The C++ and JavaScript implementations are kept in parity at two levels:

1. **AST Parity** — Both produce identical parse trees for the same input (validated by snapshot matching)
2. **Operator Parity** — Both support the same set of render operators (documented in [../docs/render-operator-parity.md](../docs/render-operator-parity.md))

Cross-language parity tests run automatically via:
```bash
npm run test-parity-contract-all  # from root
```
